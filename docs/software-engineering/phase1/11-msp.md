# فصل ۱۱ - تهیۀ MSP (برنامۀ زمان‌بندی پروژه)

## ۱۱-۱. روش و محدودۀ برنامه

این فصل، برنامۀ زمان‌بندی فاز یک پروژۀ درسی رنتینو را با ساختار شکست کار (WBS)، وابستگی‌ها، مدت‌ها، منابع و مسیر بحرانی ارائه می‌کند. برنامه به‌گونه‌ای طراحی شده است که مستقیماً در Microsoft Project (MSP) یا ابزارهای سازگار (ProjectLibre، GanttProject) قابل بارگذاری باشد. جدول ۱۱-۵ ستون‌های ورودی MSP را دارد.

**مبانی برنامه:**

- **تاریخ شروع:** شنبه ۲۵ مهر ۱۴۰۵ - ۲۰۲۶-۱۰-۱۷.
- **تاریخ ارائه:** سه‌شنبه ۵ آبان ۱۴۰۵ - ۲۰۲۶-۱۰-۲۷.
- **تاریخ نسخۀ آمادۀ بازبینی:** جمعه ۱ آبان ۱۴۰۵ - ۲۰۲۶-۱۰-۲۳.
- **تقویم:** گزینۀ فشردۀ ب؛ شنبه تا چهارشنبه روز کاری کامل، پنجشنبه و جمعه در هفتۀ آخر به‌عنوان روز جبرانی/بافر در نظر گرفته شده‌اند. این تصمیم، یک «فرض برنامه‌ریزی» است و باید در جلسۀ شروع تأیید شود.
- **واحد مدت:** روز کاری (نه ساعت) برای سادگی کنترل.
- **منابع:** شش عضو تیم، هر نفر با نقش اصلی و نقش پشتیبان.

## ۱۱-۶. مسیر بحرانی

مسیر بحرانی، زنجیره‌ای است که تأخیر در هر حلقۀ آن، تاریخ ارائه را جابه‌جا می‌کند. این زنجیره از فعالیت ۱.۱ آغاز می‌شود و به نقطۀ عطف M2 می‌رسد:

1. ۱.۱ آغاز پروژه و تثبیت دامنه
2. ۲.۱ مرور بازار و ۲.۲ تحلیل رقبا (هم‌زمان)
3. ۲.۳ نیازهای بازار
4. ۳.۱ پیش‌نویس نیازمندی‌ها و سپس ۳.۲ تجمیع و ۳.۳ بازبینی ردیابی
5. ۶.۳ یکپارچه‌سازی سند
6. ۶.۴ بازبینی کیفیت
7. M1 نسخۀ آمادۀ بازبینی
8. ۷.۱ اسلاید و ۷.۲ تمرین
9. M2 ارائه

فعالیت‌های ۴.۱ (اهداف)، ۴.۲ (ریسک‌ها) و ۴.۳ (فناوری) پیش‌نیاز ۵.۱ هستند و پیش از ۶.۳ تکمیل می‌شوند، اما بر مسیر بحرانی قرار ندارند.

**مدت مسیر بحرانی:** ۱۰ روز کاری (۱۷ تا ۲۷ اکتبر)، با احتساب روزهای جبرانی.

**شناوری (Float):**

- فعالیت ۴.۳ (فناوری) یک روز شناور دارد؛ می‌تواند تا ۲۱/۰۷ ادامه یابد بدون تأخیر در M1.
- فعالیت ۵.۱-۵.۳ (MSP) یک روز شناور دارد.
- فعالیت ۶.۱-۶.۲ (تعاریف/مراجع) یک روز شناور دارند.
- **هیچ شناوری برای ۳.۲، ۳.۳، ۶.۳ و ۶.۴ وجود ندارد.** تأخیر در تجمیع FR یا یکپارچه‌سازی، مستقیماً M1 را جابه‌جا می‌کند.

**اقدام کاهش ریسک زمان‌بندی:** تولید هم‌زمان قالب سند و جدول‌های پایه در روز اول؛ تجمیع تدریجی به‌جای تجمیع یک‌باره در روز آخر؛ بازبینی داخلی در ۳۰/۰۷ نه ۰۱/۰۸.

## ۱۱-۷. ماتریس RACI

**R** = مسئول اجرا، **A** = پاسخ‌گوی نهایی، **C** = مشورت‌شده، **I** = مطلع.

**جدول ۱۱-۴. RACI فاز یک**

| فعالیت | محمد نعیم | معین نوری | محمد سجاد | امیرحسین ترک | امیررضا | ارشیا احمدی |
|---|---|---|---|---|---|---|
| تثبیت دامنه | A/R | C | C | C | C | C |
| بررسی بازار | A | R | C | I | C | I |
| تحلیل رقبا | A | C | R | I | C | I |
| نیازهای بازار | A | R | C | I | C | I |
| جمع‌بندی اهداف | A | I | I | I | C | R |
| فرصت‌ها و ریسک‌ها | A | C | C | C | R | I |
| نیازمندی‌های کارکردی | A | C | R | C | C | C |
| تکنولوژی‌ها | A | I | C | R | C | I |
| WBS و زمان‌بندی | A | C | I | C | R | I |
| RACI | A | C | I | I | R | C |
| تعاریف و سرنام‌ها | A | C | C | C | C | R |
| مراجع | A | R | C | C | C | C |
| یکپارچه‌سازی | A/R | C | C | C | C | R |
| کنترل کیفیت | A | C | R | R | C | C |
| اسلاید ارائه | A/R | C | C | C | C | R |
| ارائه | A/R | R | R | R | R | R |

**اصل RACI:** هر فعالیت دقیقاً یک «A» دارد. سرگروه، پاسخ‌گوی نهایی است، اما اجرای پژوهش، نیازمندی، ریسک، فناوری و برنامه‌ریزی بین اعضا توزیع شده است.

## ۱۱-۱۰. جمع‌بندی برنامه

1. **برنامه، ۱۰ روز کاری با تاریخ ارائۀ ثابت است.** مسیر بحرانی از پژوهش به تجمیع نیازمندی‌ها و سپس یکپارچه‌سازی می‌گذرد.
2. **شناوری اصلی در بخش‌های فناوری، MSP و تعاریف است.** تجمیع FR و یکپارچه‌سازی، گلوگاه‌اند.
3. **RACI، مالکیت را روشن می‌کند.** هر فعالیت یک پاسخ‌گوی نهایی دارد و اجرا بین اعضا توزیع شده است.
4. **بافر، بخشی از برنامه است، نه نشانۀ ضعف.** روزهای ۰۲/۰۸ تا ۰۴/۰۸ برای اصلاحات و تمرین رزرو شده‌اند.
