# راهنمای کیت Claude برای Lensloop

این کیت پروژه‌ی اجاره‌ی تجهیزات عکاسی (فارسی، راست‌به‌چپ، تومان، تاریخ شمسی) را برای کار خودکار و کم‌مصرف با Claude Code آماده می‌کند. دستورالعمل‌های داخلی عمداً انگلیسی‌اند (دقیق‌تر و ارزان‌تر برای مدل)؛ خروجی‌ها و متن‌های سایت فارسی هستند.

## نصب (۳ دقیقه)
1. محتوای این پوشه را در **ریشه‌ی پروژه‌ی lensloop** کپی کنید (کنار `package.json`). فایل‌های `CLAUDE.md`، `.mcp.json`، پوشه‌ی `.claude/` و `docs/` باید آنجا باشند.
2. محتوای `.gitignore.additions` را به `.gitignore` اضافه کنید.
3. در ریشه‌ی پروژه `claude` را اجرا کنید و بنویسید: `/bootstrap`
4. فونت **Vazirmatn (نسخه‌ی variable، فرمت woff2)** را در `public/fonts/` بگذارید (از CDN خارجی استفاده نمی‌شود).

## کار روزمره
| دستور | کار |
|---|---|
| `/bootstrap` | یک بار: نقشه‌ی پروژه، اسکریپت‌ها، vitest، تأیید فرضیات محصول |
| `/next-task` | بعدی‌ترین کار نقشه‌راه را کامل انجام می‌دهد (برنامه، ساخت، تست، بازبینی، commit) |
| `/feature <شرح>` | ساخت یک قابلیت دلخواه |
| `/page <مسیر>` | ساخت/بازطراحی یک صفحه با دیزاین سیستم و بررسی تصویری |
| `/brand <رنگ‌ها>` | تغییر هویت بصری فقط با توکن‌ها |
| `/review` | بازبینی مستقل تغییرات (منطق، امنیت، UX، RTL) |
| `/ship-check` | گیت قبل از انتشار با گزارش GO / NO-GO |

برای شروع تقریباً همه‌چیز: `/bootstrap` و بعد چند بار `/next-task`. بین کارهای نامرتبط `/clear` بزنید.

## چه چیزی داخل کیت است
- **CLAUDE.md**: قوانین سخت (RTL، ریال/تومان، توکن‌ها، Server Components)، دستورها و قواعد صرفه‌جویی توکن. عمداً کوتاه است.
- **۹ مهارت** (`.claude/skills`، فقط در صورت نیاز بارگذاری می‌شوند): `feature-loop` (حلقه‌ی کاری)، `rtl-persian-ui`، `design-system`، `ux-flows`، `rental-domain`، `iran-integrations`، `nextjs-conventions`، `template-migration`، `testing-verification`.
- **۵ ایجنت**: `code-reviewer`، `ux-rtl-auditor` (با اسکرین‌شات واقعی)، `test-writer`، `feature-planner`، `persian-copywriter`.
- **هوک‌ها**: بعد از هر ویرایش، کلاس‌های فیزیکی (`ml-`, `text-left` …)، رنگ خام و خطای eslint را فوراً به Claude برمی‌گرداند؛ در شروع هر نشست، کار بعدی را نشان می‌دهد.
- **اسکریپت‌های RTL**: `npm run rtl:scan` (ممیزی)، `npm run rtl:fix` (تبدیل خودکار کلاس‌ها بدون مصرف توکن).
- **قالب‌های تست‌شده**: قیمت‌گذاری، دسترس‌پذیری و ماشین وضعیت رزرو، فرمت‌های فارسی/شمسی، اعتبارسنجی کد ملی/شبا/کارت/موبایل، OTP. (۶۴ تست پاس شد؛ با `vitest` هم‌خوان است.)
- **docs/**: PRD، نقشه‌راه فازبندی‌شده، مدل دامنه، دیزاین سیستم، فلوهای UX و رجیستری تصمیم‌ها.

## موارد نیازمند تصمیم شما
در `docs/PRD.md` بخش «فرضیات» همه‌چیز پیش‌فرض دارد؛ `/bootstrap` از شما می‌پرسد:
تک‌فروشنده یا مارکت‌پلیس، نحوه‌ی ودیعه، روش ورود، برند/رنگ. پاسخ ندهید، پیش‌فرض‌ها اعمال می‌شود.

## محدودیت‌های صادقانه
- کیت بدون دیدن کد واقعی ساخته شد (فقط `package.json`). `/bootstrap` ساختار واقعی را کشف و `docs/REPO-MAP.md` را می‌سازد. اگر ساختار پروژه با فرضیات (مثلاً مسیر `app/` یا alias `@/`) فرق کرد، Claude باید در `docs/DECISIONS.md` ثبت و اصلاح کند.
- مستندات Zarinpal به‌صورت خودکار قابل دریافت نبود. مهارت `iran-integrations` جریان درگاه را از دانش عمومی نوشته و صراحتاً می‌گوید قبل از کدنویسی endpointها با مستندات رسمی تطبیق داده شوند.
- مسیر دقیق خروجی `react-day-picker/persian` در نسخه‌ی ۱۰ باید با context7 تأیید شود.
- فعلاً بک‌اند وجود ندارد؛ لایه‌ی `lib/data` با داده‌ی آزمایشی شروع می‌شود (D-004).
- کلیدهای واقعی (درگاه، پیامک) را خودتان در `.env.local` بگذارید؛ هرگز در چت نفرستید.

## نکته‌ی مصرف توکن
Claude طبق CLAUDE.md اول Grep می‌کند، فقط بازه‌ی لازم فایل را می‌خواند، جست‌وجوهای بزرگ را به ایجنت‌های فرعی می‌سپارد و کارهای مکانیکی (RTL) را با اسکریپت انجام می‌دهد، نه با مدل.
